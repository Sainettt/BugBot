# 04 — Decision Log

Append-only. Newest at the bottom. Format: date · decision · rationale.

- **2026-09-22 · Multi-project from day one** — `Project` is a first-class entity; connecting a project is configuration in the cabinet, never a code change. First project MAGGuarantee, next MAGSpace. (PLAN.md v2 §0, §3.)
- **2026-09-22 · One schema, `projectId` on every project-scoped row** — no per-project tables or databases. Rationale: migrations would multiply per project, connecting a project would need DDL, cross-project queue and stats would be painful; differing report shapes are covered by the form config. (PLAN.md §8.)
- **2026-09-22 · Reporter auth = handoff token issued by the connected project** — the project (where the user is already signed in) signs a short-lived token (`iss` = slug, `aud` = `bugbot`, `exp` ≈ 60 s, one-time `jti`, claims `sub`/`email`/`name`/`roles`/`locale`) with its private key and redirects to BugBot; BugBot verifies with the public key from the project config and opens a project-scoped session. Chosen over verifying the project's own JWT (lives in an HttpOnly cookie on another domain), embedding the form in the project, or syncing users + magic link. External carriers pass the same way as employees. (PLAN.md §5, user confirmed "токен супер решение".)
- **2026-09-22 · Asymmetric signature (ES256) for handoff tokens** — a leak of BugBot's config must not allow forging a sign-in. The project keeps the private key.
- **2026-09-22 · Owner sign-in = Google id_token + e-mail allowlist in env** — `ADMIN_EMAILS` (comma-separated so a second person is an env edit, not code). Verified server-side (signature, issuer, audience, `email_verified`). Separate from the project auth adapters. No password fallback: e-mails keep arriving if Google is down. (User choice.)
- **2026-09-22 · Cabinet is the source of truth, e-mail is a notification** — the owner's main screen is the cross-project feed of reports with the agent's output; the e-mail carries a summary, a link to the report card and `report.md` + `report.json` attachments. (User request.)
- **2026-09-22 · Report analysis status ≠ owner triage status** — `queued/running/done/failed` is what the pipeline did; `new/seen/handled/archived` is what the owner did. Two fields.
- **2026-09-22 · First agent provider = Claude Code headless (`claude -p`) behind a provider interface** — model, effort and limits per project (and optionally per report kind). Other agentic CLIs, the Claude Agent SDK or a direct-API loop are later providers; queue, prompts, validation and mail stay provider-agnostic. (PLAN.md §6.)
- **2026-09-22 · Prompt = layers** — base preset (bug / idea, versioned in git) → project brief (config, versioned in DB) → project overrides → result JSON schema → report data in an explicitly untrusted block. Result JSON is validated on the backend; markdown is rendered by the backend, not by the agent.
- **2026-09-22 · Agents ported from MAGSpace** — planner, researcher, code-reviewer, test-writer, debugger, security-auditor, docs, adapted to BugBot's hot spots (project isolation, handoff verification, runner sandbox, queue idempotency); plus a BugBot-specific **preset-designer** for the analysis prompts, result schemas and project briefs.
- **2026-09-22 · Docs in English, PLAN.md in Russian, conversation in Russian** — same convention as MAGSpace; code, DB and identifiers are English anyway. Connected projects' vocabulary (przewoźnik, wniosek, stanowisko) stays untranslated. (User choice, recommended option.)
- **2026-09-22 · Queue = `Job` table in Postgres** — workers dequeue with `SELECT … FOR UPDATE SKIP LOCKED`; "one running analysis per project" is a partial unique index on `(projectId) WHERE status = 'RUNNING'`; retries, backoff and heartbeat are columns. No Redis / BullMQ in v1 — one database, and the cabinet shows jobs next to reports. (User choice, recommended option.)
- **2026-09-22 · Report fields = hybrid** — core columns shared by all projects (`kind`, `title`, `description`) for lists and search; every other form field of a project in a self-describing JSONB snapshot `[{key, label, value}]` so old reports stay readable after the form changes. Forms are defined in the project config. (User choice, recommended option.)
- **2026-09-22 · Audit = `HistoryEvent`** — MAGSpace pattern: actor (owner user or project user), project, operation, entity, JSON payload with the diff. Config changes are logged by field name; secret-bearing fields never by value. (User choice, recommended option.)
- **2026-09-22 · Prisma, cuid ids, MAGSpace naming conventions** — English enums in UPPER_SNAKE, `createdAt` / `updatedAt` everywhere, `///` doc comments in the schema, enums mirrored in `packages/shared`.
- **2026-09-22 · Reporter sessions are DB-backed (`ProjectSession`)** — same pattern as MAGSpace's `Session`; blocking a user or archiving a project revokes sessions immediately instead of at cookie expiry. Guards read roles and `isBlocked` live from `ProjectUser`. (User choice, recommended option.)
- **2026-09-22 · Agent run logs live in the DB (`AgentRun.log`, text)** — one place, visible in the cabinet, searchable; `logStorageKey` reserved for a later move to file storage without a schema change. (User choice, recommended option.)
- **2026-09-22 · Attachments are uploaded in the same multipart request as the form** — up to `limits.maxAttachments` × `limits.maxAttachmentBytes`; every attachment has a report, no drafts, no orphan cleanup. (User choice, recommended option.)
- **2026-09-22 · Retention: run logs 90 days, everything else forever** — a nightly job nulls `AgentRun.log` older than `AppSetting.logRetentionDays` (keeps `logBytes` / `logPurgedAt`); reports, results, attachments and usage are never purged; expired sessions and used handoff tokens are deleted. Per-project override is a later addition. (User choice, recommended option.)
- **2026-09-22 · Two session tables, not one** — `OwnerSession` and `ProjectSession` have different subjects, cookies, TTLs and guards; separate tables make cross-use impossible by construction. (02-entities.md §8.)
- **2026-09-22 · Per-project report numbers from `Project.reportCounter`** — incremented under the row lock in the submit transaction; shown as `<codePrefix>-<number>` (`MAGG-42`). Prefix and whether ideas share the sequence are still open (02-entities.md §9).
- **2026-09-22 · Latest successful run is the report's current run** — `Report.currentRunId` is moved in the run's own transaction; earlier runs stay for comparison. Hand-picking is a possible later addition.
- **2026-09-22 · No retry on result-schema failures** — one repair pass inside the same run; if still invalid the job fails without retry (same prompt → same failure). Infrastructure failures retry with backoff.
- **2026-09-22 · E-mail is at-least-once** — the `Notification` row is created in the run's transaction (unique per run/kind/channel/recipient); a crash between SMTP and the status update may re-send once. Exactly-once not worth provider idempotency keys for one owner mailbox.
- **2026-09-22 · Default limits for a new project** — 5 reports per user per day, 5 attachments of 10 MB each, `image/png` / `image/jpeg` / `image/webp` / `application/pdf`. Editable per project in the cabinet. (User confirmed.)
- **2026-09-22 · Report code = `<codePrefix>-<number>`, prefix from the project name** — first four letters upper-case: MAGGuarantee → `MAGG-52`, MAGSpace → `MAGS-52`; editable before the first report; bugs and ideas share one per-project sequence. (User choice.)
- **2026-09-22 · `TriageStatus` keeps `IN_PROGRESS`** — five states: NEW, SEEN, IN_PROGRESS, HANDLED, ARCHIVED. (User confirmed.)
- **2026-09-22 · Owner cabinet UI in English and Polish** — i18n dictionary pattern from MAGSpace (`pl` + `en`, compile-checked keys, no hard-coded copy); English is the default, the switch persists per owner. Project forms keep their own language from `Project.formLocale`. The agent's report language stays a per-project setting (`reportLocale`, default `ru`). (User choice; default order is an assumption — English was named first.)
- **2026-09-22 · Standard ports behind Caddy** — web 3000, api 3001, postgres 5432 inside the containers; Caddy routes by host name on the VPS. Host-side ports for a local run next to MAGSpace / MAGGuarantee are env variables. (User decision.)
- **2026-09-22 · Owner OAuth client in a new Google Cloud project** — own consent screen and redirect URIs, no coupling to MAGSpace's client. Danyil creates it. (User decision.)
- **2026-09-22 · Visual source = the Relay design system (Claude Design)** — committed verbatim at `design/relay/` (version `1790069834-cd20`); the look is binding, Relay's names and copy are not. Mapping and deliberate differences in 05-design-ui.md. (User decision; supersedes plan 01's earlier "reuse MAGSpace's shell" call.)
- **2026-09-22 · Keep the `rl-*` class names and the tokens verbatim** — `bundle.css` is copied as `relay.css`, `tokens.css` is generated from `tokens.json`; a future re-sync from the design system is a diff, not a rewrite. Tailwind is used for layout utilities only.
- **2026-09-22 · Cabinet navigation = Flow (Reports, Ideas) + System (Projects, Runs, Settings)** — Relay's "Журнал анализа" becomes the Runs page over `AgentRun`; dashboard tiles follow Relay (Reports · 24 h, Analysed, Failed, Tokens/cost); queue depth is a top-bar badge, not a tile.
- **2026-09-22 · "Needs a human" is derived, not stored** — shown for `DONE` runs whose result says `is_bug = unclear` or `confidence < 0.5`; `AnalysisStatus` stays four values. Triage buttons map onto `TriageStatus`: bug In progress / Forward / Duplicate → `IN_PROGRESS` / e-mail action / `ARCHIVED`; idea Backlog / Postpone / Reject → `IN_PROGRESS` / `SEEN` / `ARCHIVED`.
- **2026-09-22 · Relay features not in v1** — fallback model on 429, mail severity threshold, subject template placeholders, reply to author, duplicate detection, "hide author contacts" switch, CSV export, in-app context collector (app version / screen / last actions). Each is listed in 05-design-ui.md §5 with the plan it belongs to, if any.
- **2026-09-24 · Models: Opus for bugs, Fable for ideas** — spike tests on a separate machine (Danyil) showed Opus best for bug analysis and Fable best for the boss's ideas / plans. `Project.modelBug` defaults to `opus`, `Project.modelIdea` to `fable` (Claude Code aliases; a full id may be pinned per project). The run stores the concrete model id the CLI reports, not the alias. (User decision.)
- **2026-09-24 · Provider authentication is an open question; PLAN.md v2's "API key in the runner env" is no longer a settled fact** — Danyil prefers the Claude subscription (long-lived token from `claude setup-token` in `CLAUDE_CODE_OAUTH_TOKEN`) over an `ANTHROPIC_API_KEY`. Found while updating the docs: the Claude Code legal-and-compliance page says OAuth login is for "ordinary use of Claude Code", that products and services should use API key authentication, and that routing requests through Free / Pro / Max credentials on behalf of one's users is not permitted; the subscription token is also not read in `--bare` mode. Both mechanisms are described in PLAN.md §6.2; the runner reads whichever variable is set. Decision pending in PLAN.md §13.
- **2026-09-24 · Provider auth = Claude subscription via `claude setup-token`** — settles the open question above. Rationale (Danyil): this is the test stage, and pay-as-you-go during local development would burn money for nothing. The one-year OAuth token lives in `CLAUDE_CODE_OAUTH_TOKEN` of the runner container; switching to an API key later is one env variable (`ANTHROPIC_API_KEY` takes precedence — never set both). Consequences: no `--bare`, so the runner isolates itself from the analysed repo's hooks / MCP config by running from a neutral cwd with `--add-dir` (details in plan 03); subscription rate windows are shared with the owner's interactive use; `budgetUsd` is nominal. The policy risk is accepted knowingly and mitigated by the next decision. (User decision.)
- **2026-09-24 · No automatic analysis: the owner presses "Send to Claude"** — a submitted report gets `analysisStatus = NOT_SENT` and a `REPORT_RECEIVED` e-mail to the recipients of its kind; a `Job` is created only by the owner's cabinet action (`REPORT_ANALYZE`; reruns stay `REPORT_RERUN`). Reason: keeps every Claude run a personal action of the subscription holder instead of a service routing other users' requests — the Claude Code policy's "ordinary use". Still a grey zone (the call goes through BugBot's own API); revisited when moving to production or API-key billing. Reverses the 2026-09-22 "no `REPORT_RECEIVED` e-mail" note in 02-entities.md §7. (User decision.)
- **2026-09-24 · Ideas on Opus too, Fable stays optional** — revises the models entry above: `modelIdea` defaults to `opus` like `modelBug` for the test stage on the subscription; `fable` remains a per-project value (the spike tests found it best for the boss's ideas). (User decision.)
